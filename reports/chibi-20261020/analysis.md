# ผลวิเคราะห์ Chibi และการปรับ RigAndBone2D

ไฟล์นี้เหมาะสำหรับเริ่มทำ cutout skeletal animation แบบภาพแข็งแยกชิ้น ยังต้องเก็บขอบและรอยต่อก่อนใช้เป็น asset รุ่นส่งเกม

## สิ่งที่ตรวจพบจากไฟล์จริง

- PNG RGBA ขนาด 1122 × 1402 พิกเซล มีพิกเซล alpha เป็นศูนย์ 914,429 จากทั้งหมด 1,573,044 พิกเซล พื้นหลังดำที่เห็นในการ preview จึงไม่ใช่พื้นหลังทึบของไฟล์ทั้งหมด
- SHA-256 ของต้นฉบับคือ `cb69cf4309dab401db98f6db7ef8b15d1be3982f302f963a7d00519fa71d95b3` ตรวจซ้ำหลังเตรียมชิ้นแล้วตรงกัน
- ภาพตัวเต็มฝั่งซ้ายเป็นภาพอ้างอิง ส่วนแยกฝั่งขวาตัดออกมาได้ 16 ชิ้น ได้แก่ หัว คอ ลำตัว สะโพก และต้นแขน ปลายแขน มือ ต้นขา หน้าแข้ง เท้า อย่างละสองข้าง
- ตา คิ้ว ปาก และหูรวมอยู่ในชิ้นหัว การเปลี่ยนสีหน้าจึงต้องเปลี่ยนหัวทั้งชิ้นในชุดนี้ ยังไม่มีชิ้นตาปิดหรือปากสำหรับพูด
- เสื้อรวมอยู่กับลำตัว และกางเกงบางส่วนติดต้นขา การเปลี่ยนชุดทั้งชุดควรเปลี่ยนลำตัว สะโพก และต้นขาที่เกี่ยวข้องใน batch เดียว
- ภาพเอียงสามส่วนสี่และมีเงาวาดติดอยู่กับชิ้น การหมุนแรงหรือกลับด้านอาจทำให้แสงและรูปทรงดูผิด ข้อนี้เป็นการประเมินจากภาพ ไม่ใช่ผลทดสอบ gameplay

## ความพร้อมของภาพ

| ส่วน | สิ่งที่สังเกตจากภาพ | งานก่อนส่งเกม |
| --- | --- | --- |
| ขอบภาพ | มีเศษขอบสีแดงและสีปนบางจุด | เก็บขอบบนพื้นหลังสว่างและมืด |
| ข้อมือ | ปลายแขนและมือแตะกันใน sheet บางข้าง | แยก contour ให้ครบและวาดส่วนซ้อนใต้ข้อต่อ |
| ศอกและเข่า | มีเส้นขอบและหน้าตัดปลายชิ้น | ตรวจท่างอมากและเติมส่วนที่เผยออก |
| คอ | มีคอแยก และลำตัวมีคอเสื้ออยู่แล้ว | ปรับการซ้อนให้ไม่เห็นคอเสื้อซ้ำ |
| ใบหน้า | รายละเอียดติดหัวทั้งหมด | เตรียมหัวทางเลือก หรือแยกตาและปากก่อนทำ facial rig |

การตัดรอบที่สองใช้เส้นแบ่งข้อมือที่ y674 จึงเป็นชิ้นสำหรับตรวจ rig ไม่ใช่การซ่อมภาพด้วยมืออย่างสมบูรณ์ เก็บผลรอบแรกไว้ที่ `examples/chibi-20261020/parts` เพื่อเปรียบเทียบ ใช้ `parts-v2` กับ recipe ปัจจุบัน

## โครงสร้างที่เลือก

ใช้ bone ID เป็นตำแหน่งติดภาพที่คงที่ แต่ละ Bone เก็บภาพที่ฝังในโปรเจกต์อยู่แล้ว Renderer ใช้ length, width และ pivot เพื่อวาดภาพ ส่วนคีย์เฟรมเก็บมุมกระดูก การเปลี่ยน image เพียงค่าเดียวจึงใช้ animation เดิมต่อได้

ลำดับการทำงานคือ PNG sheet → manifest ตัดชิ้น → recipe → ProjectCommands และ ProjectStore → sampler และ Stage renderer → preview และ sprite sheet ทั้ง GUI และ API ใช้คำสั่งเปลี่ยนภาพตัวเดียวกัน

เปรียบเทียบทางเลือกแล้วเลือกคำสั่ง `replace_image` ที่ไม่เปลี่ยน schema อีกทางคือ registry เก็บ skin และ attachment หลายชุด ซึ่งต้องกำหนด migration การเลือกภาพ และการส่งออกใหม่ จึงยังไม่เพิ่มระบบคลังชุดในงานนี้ การเปลี่ยนหลายส่วนพร้อมกันใช้ `batch` ที่มีอยู่แล้วได้

หลัก Model the Domain ทำให้ใช้ stable bone ID เป็น slot เดิม ส่วน Prove It Works ทำให้ตรวจทั้งข้อมูลที่บันทึกและพิกเซล render จริง

## ผลงานที่สร้าง

- `recipes/chibi/parts.assets.json` ระบุ crop แบบทำซ้ำได้จากต้นฉบับ
- `examples/chibi-20261020/parts-v2` มี PNG โปร่งใส 16 ชิ้น
- `recipes/chibi/idle.rigrecipe.json` มี root ที่ไม่แสดงภาพและกระดูกชิ้นส่วน 16 ชิ้น
- `examples/chibi-20261020/Chibi.rig2d` มี idle ตัวอย่าง 2 วินาที 5 คีย์เฟรม ใช้ตรวจการประกอบและการเคลื่อนไหวเบา ๆ ยังไม่ใช่ walk หรือ combat animation
- `reports/chibi-20261020/preview` มี GIF, sprite sheet 24 เฟรม และ quality report
- `examples/chibi-20261020/Chibi-hand-swapped.rig2d` สาธิตเปลี่ยน hand-front โดยนำภาพ hand-back มาใช้เพื่อให้ตรวจเห็นความต่าง ไม่ใช่ชิ้นอุปกรณ์ใหม่
- `swap-proof.json` ยืนยันข้อมูลทั้งหมดนอกจากภาพมือเป้าหมายเหมือนเดิม และภาพ render ต่างเฉพาะบริเวณมือเมื่อเทียบที่เวลา 0.5 วินาที

## วิธีเปลี่ยนชิ้นส่วน

1. เปิด `dist/RigAndBone2D.app` และโปรเจกต์ `examples/chibi-20261020/Chibi.rig2d`
2. เลือกกระดูกเป้าหมายในรายการด้านซ้าย เช่น `hand-front`
3. กด **Replace PNG…** ในแผงด้านขวา แล้วเลือก PNG ใหม่
4. ตรวจท่าหลายเวลา แล้วกด **Save…** เพื่อบันทึก

Replace PNG เก็บขนาด จุดหมุน parent และคีย์เฟรมเดิม ส่วน Import PNG เดิมจะคำนวณความกว้างให้ตามสัดส่วนภาพใหม่ ภาพทดแทนต้องจัดข้อยึดและขอบ canvas ให้ตรงกับภาพเดิม ไม่เช่นนั้นภาพอาจยืดหรือเลื่อน แม้ค่าของ rig ไม่เปลี่ยน

ตัวอย่าง API ใช้ SDK เพื่อส่ง revision ล่าสุดโดยอัตโนมัติ

```python
from rigtools.client import AgentClient
with AgentClient() as client:
    client.request('replace_image', '/absolute/path/Character.rig2d',
                   bone='hand-front', image='/absolute/path/new-hand.png')
```

เรียกจาก Python ที่มี `scripts` อยู่ใน import path หากเปลี่ยนหลายส่วน ใช้ `client.request('batch', project, operations=[...])` แต่ละ operation เป็น `replace_image` พร้อม bone และ image การบันทึกเกิดครั้งเดียว และเมื่อรายการใดผิดทั้งหมดจะไม่ถูกบันทึก

## ผลตรวจ

Release build ผ่าน ตรวจซ้ำด้วย `tests/agent_smoke.py`, `tests/agent_workflow.py` จำนวน 15 tests, `tests/render_orientation.py`, `tests/demo_reproducibility.py` และ `tests/asset_replacement.py` จำนวน 5 tests ผ่านทั้งหมด

Preview ตรวจ 24 เฟรมที่ 12 fps ไม่พบเฟรมว่างหรือภาพชนขอบ และคีย์เฟรมต้นกับท้ายตรงกัน อ่านภาพที่ render เวลา 0 และ 0.5 วินาทีแล้ว การเคลื่อนไหวเบาและรอยต่อยังต้องเก็บงานตามตารางด้านบน

ทดสอบ GUI เลือก hand-front กด Replace PNG เลือก hand-back.png แล้ว Save เป็น Chibi-gui-replacement.rig2d ผ่านหน้าจอจริง ตรวจ JSON ที่บันทึกแล้วพบว่าต่างจากต้นฉบับเพียง bones[10].image ตัวเลขขนาดและ pivot บน inspector ตรงเดิม หลักฐานอยู่ใน gui-proof.json และ evidence/editor.png รอบแรกเครื่องมือ paste ไม่เปลี่ยน path จึงเลือกไฟล์ผิดและแอปปฏิเสธด้วย Unsupported image extension จากนั้นใช้ accessibility ตั้งค่า path และอ่านกลับก่อนเปิด PNG ที่ถูกต้อง

แอปใช้ rigid cutout ไม่มี mesh deformation หรือ IK การรับรองผลนี้ครอบคลุมไฟล์ rig และ preview ในเครื่อง ยังไม่ได้ทดสอบการนำเข้าเกม Game Magic Idle หรือประสิทธิภาพ runtime ในเกม
